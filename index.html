Independent project · Distributed API protection

Distributed API Rate Limiter

A sliding-window limiter that keeps each user's request history in shared Redis state instead of a single application's memory. Used atomic Lua execution to make cleanup, counting and admission one operation, with clear HTTP responses and an explicit Redis-outage policy.

10 requests / 60 secondsConfigured per-user demo limit; a rolling window
  • Java 21
  • Spring Boot
  • Redis
  • Lua
  • REST APIs
Engineering details
  • Tracked per-user timestamps in Redis sorted sets and executed window cleanup, request counting, allow/reject decisions and insertion atomically.
  • Returned HTTP 429 and Retry-After for excess requests, with remaining-quota headers for accepted calls.
  • Expired inactive keys and implemented a documented fail-open policy with warning logs when Redis is unavailable.
  • Documented request-limit and dependency-outage verification, including the availability trade-off of allowing traffic during Redis failure.
